# SUPER VIRTUAL ADVENTURE — STAGE 01 "DASH MEADOW"

> **Status**: 公開（2026-11-19）。実機でのプレイを確認しました。速度・ブレーキ・ハートの数などは `rules.js` 冒頭の `RULES` で調整できます。

横スクロールのアクションゲームを、**自分の目線**で走るゲームです。
横スクロールの「右へ進む・上へとぶ」を、「奥へ進む・上へとぶ」に置きかえました。
操作は SUPER VIRTUAL HURDLE と同じ2つだけ：**足ぶみで前へ、つま先を上げてジャンプ**。

このゲームの主役は **スピード** です。足ぶみをつづけるほど速くなり、ジャンプはとんだ瞬間の速さのまま進みます。
広い穴はダッシュしないと届かず、小さな足場は速すぎると通りすぎます。

画面上部には、同じコースを横から見た図（SIDE VIEW）がいつも出ています。
3D の一人称視点と、2D の横スクロールは、同じ1つのコースを別の向きから見たものです。

見た目は、横スクロールアクションで昔から親しまれてきた世界（青空、草の生えた土のブロック、空中のブロック、金のコイン、丸い丘）を、走る人の向きに回したものです。
主人公は ORPHE のキャラクター「ORPHEくん」（帽子・Tシャツ・斜線の短パン・スニーカー）で、生き物も同じ「白地に黒い線」の線画ふうにそろえています。
コース・生き物・絵・音楽はこの example のために作ったオリジナルで、画像ファイルも音声ファイルも使っていません（絵は小さな canvas に描いたドット絵、音は Web Audio の合成）。

## むずかしさ（タイトル画面で切りかえ）

| | ノーマル（初期設定） | やさしい |
| --- | --- | --- |
| ミスしたとき（敵・ハンマー・穴） | ハート −1 で **スタートにもどる**。コイン・ブロック・敵も元にもどる | ハート −1。その場（穴は手前）から続行 |
| チェックポイント | コースのまん中に1つだけ（通ったあとは、ミスしてもそこから） | ゾーンと助走路ごとに6つ |
| ハートが 0 | **ゲームオーバー**（RETRY で最初から） | 全回復してチェックポイントから |
| おたすけ橋 | なし | 同じ穴に2回落ちるとかかる |

ノーマルは「はじめての人はすぐミスしてスタートにもどるが、コースを覚えた人は 1 分かからずにクリアできる」むずかしさです。
やさしいは「だれでも必ずゴールできる」設定で、体験会や小さな子ども向けです。ランキングとベスト記録は別々に残ります。

## 遊び方

| 入力 | ORPHE CORE / ORPHE INSOLE | キーボード | タッチ |
| --- | --- | --- | --- |
| 走る | 足ぶみ（どちらの足でも） | `←` または `↑` を長押し | 画面の左半分を押している間 |
| ジャンプ | つま先を上げる | `→` または `Space` | 画面の右半分をタップ |
| スタート | — | `Enter` | START ボタン |
| タイトルへ | — | `Esc` | — |

- 画面の下には、**自分の足と腕**がいつも見えています（足の位置＝自分の位置。走ると腕をふり、ジャンプすると両腕が上がります）。
  上の SIDE VIEW では、同じ動きを横から見たドット絵の主人公で確かめられます。黄色い ▼ が自分です。
- 画面右上の **ORPHE CORE** パネルのスイッチを ON にして CORE を接続します（足の甲に装着。2個で両足、1個でも遊べます）。
  パネル右上の **CORE / INSOLE** で ORPHE INSOLE に切り替えられます（ページを再読み込み。選択は SUPER VIRTUAL HURDLE と共通）。
- センサーをつなぐと、パネルに **加速度の生データのグラフ**が出ます（左右の足の加速度 [G] と、つま先の角度）。
  白い点線が「足ぶみ」のしきい値で、線より上にふれている間は走ります。プレイ中も画面右下に同じグラフが出ます。
- カウントダウン中は足を止めて立ってください。その角度を「つま先上げ」の基準（ゼロ）にするので、センサーの取り付け角度が違っても同じ動きでとべます。

### スピードの使い方

| 速さ | どうなる |
| --- | --- |
| 足ぶみを始める | すぐにジョギング（4 m/s） |
| 足ぶみをつづける | 少しずつ加速して、約1.5秒でダッシュ（8〜9 m/s） |
| さらにつづける | **止まらずに加速しつづけ、最高 13 m/s**。10 m/s をこえると「はやすぎ！」。画面がゆれ、警告音が鳴る |
| 足ぶみを止める | 0.2 秒ほど惰性で進み、そのあとブレーキ。止まるまで 8 m/s から約 6 m、13 m/s からは約 15 m |
| ジャンプ | とんだ瞬間の速さのまま進む。ジョギングで 3 m、ダッシュで 6.9 m、13 m/s では 10 m とぶ。空中では速さを変えられない |

速いほどタイムは縮みますが、ジャンプは長くなり、止まれなくなり、合図を見てから動く時間がなくなります。
コースは 9 m/s くらいまでを前提に作ってあるので、**加速しっぱなしだと制御しきれずに穴へ落ちます**。どこまで攻めるかがこのゲームの勝負どころです。

道の色と画面下の **スピードゲージ** が、次に必要な速さを教えます。

- **青い矢印の道**（DASH）：この先に広い穴。足ぶみを止めずにダッシュ。十分な速さになると矢印が緑になる
- **黄色い矢印の道**（SLOW）：この先に小さな足場や点滅ブリッジ。足ぶみをゆるめる。速すぎると矢印が赤く点滅する
- スピードゲージの **緑の帯**：次の穴・次の区間に合う速さ。帯の中に入れてからジャンプ

### コースにあるもの

| もの | どうする |
| --- | --- |
| コイン | 集める（+100）。地面のコインは走って取る。アーチのコインはジャンプで取る |
| 小さな穴（2 m 以下） | どんな速さでもとびこえられる |
| 広い穴（4.6 / 5.2 / 5.8 m） | **ダッシュ**してからジャンプ。手前に長い助走路がある |
| 小さな足場（3 m） | **スピードを落として**からジャンプ。速すぎると足場をとびこす |
| プルプル（頭に芽の生えた四角い生き物） | 音楽に合わせてはねながら歩く。上からふむ（+200、続けてふむとコンボで倍）。横からぶつかるとミス |
| ダッシュまる（ゴーグルをかけた丸い生き物） | プルプルの2倍の速さで走りまわる。スタート直後にも出てくる。上からふめるが、タイミングがむずかしい |
| トゲまる（ふきげんな栗） | 動かない。ふめない。とびこえる。穴のすぐ手前やベルトの上にもいる |
| コインブロック | ジャンプして頭でたたくと割れる（+300 とコイン3枚） |
| ジャンプ台 | 乗ると大ジャンプ。上の道へ行ける |
| 点滅ブリッジ | 光っている間だけ乗れる。音楽の 8 拍のうち 5 拍だけ光る |
| ハンマー | 8 拍に 1 回落ちてくる。**STOP で足を止め**、GO で走りぬける |
| ぎゃく走ベルト | 足ぶみを止めると押しもどされる |
| 金のブロック | フィーバー（9秒間、無敵＋スピード1.25倍。生き物は当たるだけでふきとぶ） |
| ふみきり板 | 最後は走り幅とび。全力ダッシュで板ぎりぎりからとぶほど遠くへ（1 m = +300） |

ハートは3つです。ミスしたときにどうなるかは、上の「むずかしさ」で変わります。
「やさしい」では、広い穴に落ちるともう一度助走できる位置までもどり、**同じ穴に2回落ちると「おたすけ橋」がかかります**（同じ点滅ブリッジで2回落ちるとその橋は光ったままになります）。
スコアは、コイン・ブロック・ふんづけに加えて、タイム（150秒より速い 1 秒ごとに +60）、残りハート、ノーミス、走り幅とびで決まります。

### 合図とジャンプ補助

ゲームは毎フレーム、いまの状態から1秒先を2通り（そのまま走る／いまジャンプする）試しに進めて、結果をくらべています（`rules.js` の `advise()`）。

- **JUMP**：そのまま走ると何かにぶつかる・落ちる、いまとべばこえられる
- **JUMP ♪**（金色）：とばなくても平気だが、とぶとブロックやコインが取れる
- **STOP / WAIT / GO**：ハンマーと点滅ブリッジ。一度 STOP が出たら、止まるまで STOP のまま（ブレーキ中に GO に戻って混乱しないように）
- **DASH! / SLOW / OK!**：次の穴・区間に合う速さ（上の「スピードの使い方」）。SLOW は、反応する時間とブレーキの距離を見こんで早めに出る
- **着地マーク**：いまとんだら（空中では、このまま進むと）どこに下りるか。緑＝とぶべき、赤＝穴

穴ごとの「合う速さ」は、コースを読み込むときに実際のルールで試しとびして求めています（`findGaps()`）。`RULES` の数値やコースを変えても合図は正しいままです。

センサーのジャンプは、この合図を使った**ジャンプ補助**を通ります（設定で OFF にできます）。

- JUMP の合図は、とべる瞬間より約 0.3 秒**早く**出ます。人が合図を見てから動くまでの時間ぶんです
- 早すぎるつま先上げは、とべる位置に入るまで最大 0.45 秒待ってからジャンプします（合図どおりに上げれば、ちょうどの位置でとびます）
- 足ぶみの動きで「つま先上げ」を誤検出しても、とぶ理由のない場所ではジャンプしません
- 止まっているときのジャンプは常に有効です（走る前にジャンプを試せます）
- キーボードとタッチのジャンプは無視されません。合図が早く出ている間に押したときだけ、同じように少し待ってからとびます

タイトル画面の後ろで動いているデモも、同じ `advise()` だけで走っています。

## このExampleで学べること

- ORPHE CORE / INSOLE の2つの動き（足ぶみ・つま先上げ）だけで、加速・減速・停止・ジャンプを使い分けるゲームを作る方法
- センサーの「足ぶみ」は 1 歩ごとに途切れる信号。それを「走りつづけている」に変える方法（入力側の保持 `SENSOR_ACCEL_HOLD_MS` と、ルール側の惰性 `RULES.COAST_SEC`）
- ルール（DOM も three.js も使わない純粋な関数）と見た目を分ける構成。ルールは Node のテストでそのまま動く
- 先読みシミュレーションで、合図・センサーの誤検出対策・デモプレイ・「クリアできること」のテストを1つの関数でまかなう方法
- 音楽とゲームの時計を合わせる方法（BGM はレースの時計で進み、ハンマーは必ず拍の上で落ちる）
- 判定に使っている生データをその場でグラフにして見せる方法（`../GAME-SUPER-START/scope.js` を共用）

## 使うデータ

- `gotConvertedAcc`（加速度の大きさ → 足ぶみ）
- `gotEuler`（pitch → つま先上げ）

## 必要なORPHE CORE数

- 1〜2台（キーボードだけでも遊べます）

## ファイル構成

| File | Role |
| --- | --- |
| `index.html` | マークアップと、ORPHE CORE の初期化・センサーコールバック（インライン script） |
| `rules.js` | ルール。走る・加速する・止まる・とぶ・ぶつかる・ふむ、時計で動くもの（生き物・ハンマー・橋）、穴ごとの合う速さ `findGaps()`、先読み `advise()`、デモ用プレイヤー `botInput()` |
| `level.js` | コース（地面の高さ・穴・生き物・コイン・ブロック・ハンマー・橋・ゆっくり区間・チェックポイント・看板） |
| `main.js` | 進行（タイトル → カウントダウン → プレイ → 結果）、入力、ジャンプ補助、一人称カメラ、HUD（スピードゲージ）、生データのグラフ、ランキング |
| `world.js` | three.js の世界（ブロックの道、湖、丘、雲、コイン、ブロック、生き物3種、ハンマー、道の矢印、着地マーク） |
| `body.js` | 主観視点の自分の体（ORPHEくんの足と腕）。FPS ゲームと同じく、目に固定した別のシーンとして世界の上に重ねて描く。足は画面の下の端（つま先が見えるくらい）にあり、ふみ出した足が画面に入ってくる。線画ふうの輪郭 `inked()` もここ |
| `sideview.js` | 画面上部の「横から見た図」（2D canvas）。主人公と生き物はドット絵 |
| `audio.js` | Web Audio による BGM（矩形波・三角波・ノイズ。ゾーンごとに音が増える）と効果音 |
| `style.css` | スタイル |

センサー入力の受け口は `window.setAccelPressed()` と `window.gameJump()` の2つだけです（グラフ用に `window.sensorTap()` が各サンプルで呼ばれます）。
ORPHE INSOLE は `../GAME-SUPER-HURDLE/insole.js` が同じ受け口に変換します。

コースを変えるには `level.js` を編集します。`ground(a, b, h)`・`slope(a, h0, h1)`・`jelly(a, b)`・`bell(s)`・`hammer(a, phase)`・`slow(a, b, max)` などを並べるだけです。
穴の幅を変えれば、必要な速さ・道の矢印・ゲージの帯・合図は自動で変わります。
変えたあとは下のテストを実行してください。自動プレイヤーが完走できなければ、どこで止まったかが出ます。助走路の長さや、障害物どうしの間隔もテストが確かめます。

数値（速度・加速・ブレーキ・ジャンプ・重力・ハート・フィーバーの長さなど）は `rules.js` 冒頭の `RULES` で調整できます。

## Run

ローカルサーバを起動して、Chrome で開きます。

```text
http://localhost:8767/examples/GAME-SUPER-ADVENTURE/
```

three.js（0.160）とポストプロセス用アドオンを unpkg から、ドット文字のフォント（DotGothic16）を Google Fonts から読み込むため、ネットワーク接続が必要です（フォントは読み込めなくても遊べます）。

| URL の指定 | はたらき |
| --- | --- |
| `?autoplay=1` | 自動プレイヤーが本番のコースを走る（デモ動画の収録・動作確認用） |
| `?mute=1` | 音を出さない |
| `?device=insole` / `?device=core` | センサーの種類をこの回だけ指定 |
| `?device=insole&insoleSim=1` | ORPHE INSOLE のシミュレータで、実機なしで接続UI・入力の流れ・生データのグラフを確認 |

## テスト

```bash
node tests/super-adventure-rules.test.js      # ルール、コースの決まり、自動プレイヤーの完走
node tests/super-adventure-build-id.test.js   # ?v= ビルドIDの一致、import map の登録漏れ
```

`npm test` にも含まれています。自動プレイヤーで次を確かめています。

- やさしい：ダッシュする4種（全速・寄り道なし・ふだん 6 m/s・ふだん 5 m/s）はミスなしで完走。ダッシュしない2種（4 m/s・3 m/s）は広い穴ごとに2回落ち、おたすけ橋で完走
- ノーマル：ダッシュする2種はノーミス・1分以内で完走。ダッシュしないプレイヤーは最初の広い穴でゲームオーバー。ミスするとスタート（または中間ポイント）にもどり、コインや敵が元にもどること

## 実機確認

- 2026-11-19 に実機でプレイできることを確認しました。キーボード操作、自動プレイヤー、ORPHE INSOLE シミュレータ（足ぶみ → 走る、つま先上げ → ジャンプ、グラフの表示）はヘッドレス Chrome でも確認しています。
- 調整の目安（むずかしさ）：ノーマルが実際の足ぶみ操作でむずかしすぎないか。合図に反応するだけの模擬プレイヤーでは、8 m/s におさえて反応 0.25 秒なら 52 秒でクリア、加速しっぱなし（13 m/s）だと反応 0.25 秒でもゲームオーバー、反応 0.35 秒以上だと 41〜48 m 付近（トゲまると最初の穴）でゲームオーバーになる。合図どおりに 1 フレームも遅れず動く自動プレイヤーは 13 m/s のまま 36 秒でクリアできる。
  きびしすぎるときは `RULES.HEARTS` を増やすか、`level.js` の `checkpoint(..., { mid: true })` を増やす
- 調整の目安（操作）：
  - 足ぶみを続けてダッシュ（9 m/s）まで上がるか。上がりきらないときは、足ぶみの途切れで減速している。
    `main.js` の `SENSOR_ACCEL_HOLD_MS`（いま 220 ms）か `rules.js` の `RULES.COAST_SEC`（いま 0.22 秒）を長くする
  - 逆に、足を止めてからブレーキが始まるまでが遅く感じないか（上の2つの合計ぶん遅れる）
  - 3つの広い穴を、助走路の長さでとびこえられるか。きびしければ `RULES.DASH_ACCEL` を上げる（助走が短くなる）
  - STOP で止まりやすいか、ジャンプ補助の効き方、つま先上げの閾値（閾値は設定＝右上のスライダーアイコンで調整）

### ファイルを変更したとき（キャッシュ対策）

`examples/GAME-SUPER-ADVENTURE/` の `.js` / `.css` を変更したら、`index.html` 内のビルドID（例 `20261119a`）をすべて同じ新しい値に書き換えてください。
読み込まれた版はコンソールの `[ADVENTURE] build ...` で確認できます。
