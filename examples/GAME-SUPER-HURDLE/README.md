# SUPER VIRTUAL HURDLE — 110m Hurdles, stadium edition

ORPHE COREを足に装着して走る動きで進み、ハードルを越えてゴールを目指すVirtual Sports Exampleです。
夜のスタジアムで行われる「110mH 決勝」を一人称視点で走ります。

## What It Does

- Uses ORPHE CORE motion and gait data as the game input.
- Shows a 110m hurdle race as a browser game: a floodlit stadium, seven rival sprinters,
  a live big screen, and a fully synthesised stadium soundtrack.
- Provides the flagship example for the Virtual Sports category.

## 遊び方

タイトル画面で **SOLO**（1人）か **VS**（2人対戦）を選びます。

| 入力 | SOLO | VS |
| --- | --- | --- |
| 加速 | 足踏み（CORE 2個・両足） / `←` 長押し | 足踏み（CORE 1個ずつ・足の甲） / P1 `A`・P2 `←` |
| ジャンプ | つま先を上げる / `→` | つま先を上げる / P1 `D`・P2 `→` |
| スタート | `Enter` / `Space` | 同じ |
| リセット | `Esc` | 同じ |

### VS モード（2人対戦）

- 接続する CORE は SOLO と同じ2個です。1人1個ずつ足の甲に着け、**CORE 01 が PLAYER 1（左画面・4レーン）、CORE 02 が PLAYER 2（右画面・5レーン）** になります。
- 画面は左右に分割され、それぞれの一人称視点・HUD・スタミナを持ちます。相手は隣のレーンを走る姿として見えます。
- 先にゴールした方が勝ちです。片方がゴールしてから15秒たつと、もう片方は DNF になります。
- 結果画面では2人分の名前を入れてランキングに登録できます。

### ルール（設定ドロワーの「ルール」で切替）

| 項目 | 新（既定） | 従来 |
| --- | --- | --- |
| ジャンプ | 空中では加速できず、1回のジャンプで速度が約12%落ちる | 空中でも地上と同じように加速できる |
| スタミナ | **ペース配分**：巡航速度（8.4 m/s）を超えると減り始め、速いほど激しく減る。0になると「息切れ」で最高速が半分（6 m/s）になり、35%まで回復すると復帰。バー下の `PACE` 印どおりに、ゴールでちょうど使い切るのが最速 | 加速している間だけ減り、止めると回復。8%を切ると加速できない |
| ジャンプ補助 | センサーのジャンプは踏み切り位置（JUMPサインが出る範囲）でだけ跳ぶ。早すぎるつま先上げは最大0.45秒待って踏み切り位置に入った瞬間に跳び、次のハードルまで1秒以上あるとき（スタート直後・接触後の再加速・最終ハードル後）の足踏みは無視する。遅すぎるつま先上げは従来どおり接触。カウントダウンの最後の1.5秒に足を静止していると、その角度をつま先上げの基準（ゼロ）にするので、センサーの取り付け角度が違っても同じ動きで跳べる。キーボードは対象外 | センサーのジャンプは場所に関係なく常に有効、角度はセンサーの基準のまま |

3つとも「従来」にすると、リマスター前と同じルールになります。選択はブラウザに保存され、自己ベストとランキングはルール（ジャンプ×スタミナ）の組み合わせごとに別々です。同じ走りでも新ルールは1〜2秒遅くなるためで、ランキング画面には今のルールの記録だけが出ます。これまでの記録（`ranking-frozen.json` と、ルール切替ができる前に保存した記録）は「従来ルール」のランキングに残っています。

- 画面右上の **ORPHE CORE** パネルのスイッチをONにして、左足・右足のCOREを接続します。
  「足踏み 加速」「つま先UP ジャンプ」のランプで、センサーが反応しているかをスタート前に確認できます。
- スライダーアイコン（右上）で、センサー値モニター・加速度／ピッチの閾値・音量・描画品質を調整できます。
- レーン上の矢印（テイクオフゾーン）が緑に変わり **JUMP** が出たら踏み切りの合図です。合図は「いま跳べばクリアできる」一番早いタイミング（バーの約0.53秒手前）で点きます。
- スピードに乗ると、着地してから次の踏み切りまで地上にいるのは0.2秒ほどしかなく、合図を見てからでは間に合いません。空中にいる間も次のテイクオフゾーンがレーン上に見えているので、**着地と同時につま先を上げる**リズムで跳ぶのがコツです。
- 新ルールでは、むだなジャンプは損で、踏みっぱなしだと80m付近で息切れします。スタミナバーの `PACE` 印と「余力／飛ばしすぎ」の表示が配分の目安です。
- 数値は `main.js` 冒頭の定数で調整できます（`JUMP_SPEED_LOSS`、`CRUISE_SPEED`、`STAMINA_BURN_AT_MAX`、`EXHAUSTED_SPEED`、`EXHAUSTED_RECOVER_LEVEL` など）。
- ゴール後、名前を入れて「ランキング登録」を押すと、このブラウザのランキングに記録されます。

### ORPHE INSOLE で遊ぶ

接続パネル右上の **CORE / INSOLE** スイッチで、センサーを ORPHE INSOLE に切り替えられます（ページを再読み込みして切り替わり、選択はブラウザに保存されます）。

- 操作は CORE と同じです：足踏みで加速、つま先を上げてジャンプ。閾値とクールダウンも共通です。
- INSOLE は IMU に加えて圧力6chを持ちます。ゲームの判定には IMU だけを使い、圧力は走行後の分析（接地時間）と生データ記録に使います。
- INSOLE のセンサ座標系は X=右・Y=つま先・Z=上なので、つま先上げは `euler.roll` に出ます（CORE は `pitch` のマイナス）。`insole.js` がこれを CORE と同じ向きに直します。向きが逆の個体に備えて、静止時の重力方向から自動判定し、設定ドロワーの「つま先上げの向き」で手動でも反転できます。
- INSOLE の SDK と接続UI（[ORPHE-INSOLE.js](https://github.com/Orphe-OSS/ORPHE-INSOLE.js) v1.4.0 の `ORPHE-INSOLE.js` / `InsoleToolkit.js`）は、INSOLE を選んだときだけ jsDelivr から読み込みます。CORE を選んでいる間は読み込みません。
- 実機なしで試すには `?device=insole&insoleSim=1` を付けると、SDK 付属のシミュレータで接続UIとデータの流れを確認できます。

### ゴール後の分析（スコア・レーダーチャート）

ゴールすると、結果カードに **総合スコア（0〜100）と評価（S〜D）、6軸のレーダーチャート** が出ます。「詳しい分析」で、強み・課題・次の一歩のコメント、スタッツ表、ハードルごとの区間タイムを表示します。VS では2人分を重ねて比較できます。

| 軸 | 何を見ているか |
| --- | --- |
| スピード | 平均速度 |
| スタート | 号砲への反応時間と、1台目までのタイム |
| ハードリング | クリア率と、踏み切りタイミングの適正さ |
| リズム | ハードル間タイムのばらつき（小さいほど高得点）。接触などで普段の1.5倍以上かかった区間は「乱れ」として別に減点 |
| ペース配分 | PACE どおりに使えたか、息切れ・使い残しがないか |
| 後半の粘り | ラスト30mの速度が、中盤（20〜80m）の普段の速度（中央値）に比べて落ちていないか |

CORE を接続していると、ピッチ（歩/分）、歩数、左右バランス（SOLO）、足の加速度ピーク、つま先上げ角度、センサー受信レートも表示します。
INSOLE ではこれに加えて、圧力センサーから求めた接地時間（中央値）を表示します。ジャンプ補助が働いた回数（待って跳んだ回数・無視した回数）もスタッツに出ます。
いずれもゲーム内の動きから出したトレーニング用の目安で、医療的な測定値ではありません。

### 生データの記録

接続パネル（または設定ドロワー）の **「生データを記録 / REC」** をONにすると、カウントダウン開始からゴールまでを記録します。

- 記録内容：CORE の受信パケット（16進）、加速度 [G]、ジャイロ [deg/s]、クォータニオン、オイラー角、歩行解析値（gait / stride / pronation / 着地衝撃 / 足角度 / 歩数）、パケット欠落、毎フレームのゲーム状態（位置・速度・スタミナ・入力）、イベント（ジャンプ・誤ジャンプ防止で無視したジャンプ・クリア・接触・息切れ・ゴール）、ルールと閾値、分析結果。
- 保存先：このブラウザの IndexedDB（`hurdle-telemetry`）。リロードしても残ります。途中でリセットした走行も「未完走」として残します。
- 書き出し：分析画面か設定ドロワーから、最新の走行を JSON / CSV、または全走行をまとめて JSON でダウンロードできます。
- 時刻 `t` は記録開始からのミリ秒です。`events` の `go` が号砲の時刻になります。

記録はセンサーのコールバックに「記録してから元の処理を呼ぶ」形で挟んでおり、記録側で失敗してもゲームの入力には影響しません。

## このExampleで学べること

- ORPHE COREの歩行・走行データをゲーム入力に使う方法
- 2台のORPHE COREを使った足の動きの扱い
- 身体動作をそのまま競技型インターフェースにする考え方
- センサー入力（ルール）と演出（3D・音・UI）を分離する構成

## 使うデータ

- `gotConvertedAcc`
- `gotEuler`
- Gait Analysis data

## 必要なORPHE CORE数

- 2台（SOLO は1人が両足に、VS は2人が1個ずつ。キーボードだけでも遊べます）

## ファイル構成

| File | Role |
| --- | --- |
| `index.html` | マークアップと、ORPHE COREの初期化・センサーコールバック（インラインscript） |
| `main.js` | ゲームのルール（物理・スタミナ・ハードル判定・ゴール・ランキング）と進行、カメラ演出 |
| `world.js` | スタジアム（トラック、観客、照明、LEDボード、大型ビジョン、ハードル） |
| `runner.js` | ライバル走者、プレイヤーの影、一人称の腕・脚 |
| `fx.js` | ポストプロセス（ブルーム、スピードブラー）と紙吹雪・花火などのパーティクル |
| `audio.js` | Web Audioによる音響（適応型BGM、観客、足音・呼吸・号砲などの効果音） |
| `ui.js` | HUD、カウントダウン、リザルト、分析画面、ランキング、設定ドロワー |
| `analysis.js` | 走行トレースから6軸スコア・評価・コメント・スタッツを計算（DOM 非依存） |
| `insole.js` | ORPHE INSOLE 対応（SDK の読み込み、接続UIの差し替え、CORE と同じ入力への変換） |
| `telemetry.js` | センサーコールバックへのタップ、走行中のセンサー統計、生データ記録（IndexedDB）と JSON / CSV 書き出し |
| `style.css` | スタイル |

SOLO のセンサー入力の受け口は `window.gameJump()` と `window.setAccelPressed()` の2つだけです。
VS ではインラインscriptが更新する `window.devices[0/1]` を `main.js` がランナーごとに読み、同じ閾値とクールダウンで判定します。
`main.js` 冒頭の定数と `stepPlayer()` がゲームのルールで、それ以外のモジュールは演出だけを担当します。
自作ゲームのベースにするときは、ルールはそのままに `world.js` や `audio.js` を差し替えるのが簡単です。

ローカルサーバを起動して、Chromeで開きます。

### ファイルを変更したとき（キャッシュ対策）

ゲームは複数の ES モジュールでできているので、ブラウザが古いモジュールと新しいモジュールを混ぜて読み込むと動作がおかしくなります。
これを防ぐため、`index.html` で `main.js`・`style.css`・各モジュール（import map）に同じ `?v=ビルドID` を付けています。
`examples/GAME-SUPER-HURDLE/` の `.js` / `.css` を変更したら、`index.html` 内のビルドID（例 `20261114a`）をすべて同じ新しい値に書き換えてください。
`tests/hurdle-build-id.test.js` が、ID の不一致や import map の登録漏れを検出します。読み込まれた版はコンソールの `[HURDLE] build ...` で確認できます。
