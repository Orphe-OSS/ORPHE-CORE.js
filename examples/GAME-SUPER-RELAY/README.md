# SUPER VIRTUAL RELAY — バーチャルリレー 4×100m

> **Status**: 作成中（2026-11-17）。キーボードと擬似センサーで 400m の完走まで動作確認済み。実機（ORPHE CORE）では 2026-11-16 に一度動かし、その感想をもとにルールと演出を作り直しました。**作り直したあとの版は、まだ実機で確認していません。** しきい値は実機で合わせる必要があります。

ORPHE CORE 1 個を**バトン**にして、何人かで回すリレーです。座ったままでも遊べます。
[SUPER VIRTUAL HURDLE](../GAME-SUPER-HURDLE/README.md) と同じ夜のスタジアムで、走者を後ろから映します。

## 遊び方

やることは 2 つだけで、正反対です。

| どこで | すること | 画面 |
| --- | --- | --- |
| **走る区間** | CORE を**振る**。強く振るほど速い | 走者を後ろから映す。`SHAKE! 振れ！` と振りのバー |
| **テイクオーバーゾーン**（青い 30m） | 振るのを**やめて**、CORE を**動かさずに**次の人へ渡す | スローモーションになり、バトンを渡す手元のアップに切り替わる |

1. 右上のパネルで CORE を 1 個つなぎます（つながなくても `Space` キーで遊べます）。
2. タイトルで走者の名前を入れられます（任意。「,」区切りで 4 人まで）。走者の上と結果に出ます。
3. **START**。1 走が CORE を持ち、「SET」で止めて、号砲で振り始めます（[SUPER VIRTUAL START](../GAME-SUPER-START/README.md) と同じ手順）。
4. 「ZONE AHEAD　あと ◯m」が出たら、止める準備をします。
5. ゾーンに入ると時間がほぼ止まり、そこから 0.3 倍のスローモーションになって、手元のアップに切り替わります。画面いっぱいに、CORE の**角速度 X・Y・Z と加速度 X・Y・Z の生の波形**が光の線で流れます。線を帯（点線のあいだ）の中に保ったまま、次の人に手渡します。
6. ゲージが満タンになると「PASS!」。受け取った人が全力で振ります。
7. これを 3 回くり返し、4 走がゴールします。

キーボードでは、`Space` を押しているあいだが「振っている」、離すと「まったく動かしていない」です。`Enter` でスタート／もう一度、`Esc` でタイトルへ戻ります。

1 人で右手から左手に持ち替えても、2 人で往復しても遊べます。**誰が持っているかはセンサーでは分かりません。** 受け渡したかどうかは、席のみなさんで見届けてください。

## ルール

### 走る

- 速度は「振りの強さ」で決まります。**全員おなじ物差し**で、自分比ではありません。強く振るほど、人の腕で出せる限界まで速くなります。
- 振りの強さは、**手が 1 秒間に振れた角度の合計**（角速度の大きさの平均、°/s）です。振幅 × 回数にあたり、走りの「ストライド × ピッチ」と同じ形をしています。回さずに突くように振った場合は、加速度の平均（G）で測ります。

  | 振りの強さ | 速度 | 4 人の合計の目安 |
  | --- | --- | --- |
  | 150 °/s | 秒速 7.5m | 57 秒 |
  | 250 °/s | 秒速 8.7m | 49 秒 |
  | 400 °/s | 秒速 10.1m | 43 秒 |
  | 500 °/s | 秒速 10.8m | 41 秒 |
  | 800 °/s | 秒速 12.4m（人が出した最高速） | 36 秒 |

  対応は `速度 = 12.4 × (振り ÷ 800)^0.3` です。上限は 1000 °/s（センサーの測れる範囲の近く）です。
- **この数字は机上の見積もりです。** 決めた時点では、誰の振りも測っていません。250 °/s を「ふつうの人が頑張ったとき」、800 °/s を「物理的な限界」と仮定しています。結果の画面に区間ごとの振りの強さ（°/s）と回数（回/秒）が出るので、実際の値を見て、設定の「トップスピードになる振りの強さ」で合わせてください。
- ライバルの 7 チームは 40.5〜45.5 秒です（2026-11-17 の実機テストで、50 秒以上では弱すぎると分かったため）。振りが 400〜520 °/s で受け渡しをまずまずこなしたチームと同じ速さです。
- 腕を振るたびに風切り音が鳴ります。速度が一段上がると上昇音、落ちると下降音が鳴り、速度に合わせて音の高さが変わります。

### 生データの記録

走るたびに、次の内容を**このブラウザに自動で保存**します（IndexedDB。リロードしても残ります）。

- 加速度 3 軸（G）と角速度 3 軸（°/s）の生データ。SDK が届けたままの値で、約 200 Hz
- 0.05 秒ごとのゲームの状態（距離、速度、区間、ゲージ、振りの強さ、順位など）
- できごと（号砲、反応、ゾーン進入、受け渡し、ゴールなど）と結果（区間ごとの振りの平均・最大・回数を含む）
- 走者の名前、設定、しきい値、センサーのレンジ、ビルド ID

さらに、**ゴールするたびに、その 1 本を JSON で「ダウンロード」フォルダへ自動で保存します**（設定ドロワーで切れます）。2 回目の保存のときに Chrome が「複数のファイルのダウンロードを許可しますか」と聞くので、許可してください。

結果の画面の「生データ」でその 1 本を、設定ドロワーの「すべて JSON で保存」で全走行を、あとから取り出すこともできます。1 本で約 0.5 MB です。号砲リアクションの記録も同じ場所に入ります（こちらは自動ダウンロードはしません）。

### スローモーションの演出

ゾーンに入る瞬間が、この種目の見せ場です。

- **映像**：時間がほぼ止まり（0.03 倍）、そこからゆっくり 0.3 倍まで戻ります。画面が中心に向かって流れ、色が抜け、放射状の線が吸い込まれます。
- **音**：会場の音（歓声・音楽・風・足音）が 0.2 秒でこもり、その上で高い音が 3 オクターブ落ちて低い一打で着地します。スローのあいだは、細く高い音が鳴り続けます。受け渡しが終わると逆の動きで元に戻ります。

### バトンパス

受け渡しは「待つ時間」ではなく、**手の精度を問う場面**です。

| できごと | どうなるか |
| --- | --- |
| まったく動かさない | ゲージが 1.4 秒で満タン。バトンの速度は 84% 残る |
| 少し動かす（帯の中） | 動かしたぶんだけバトンの速度が落ち（動きの 2 乗に比例）、ゲージもたまりにくくなる |
| 帯の外に出る | ゲージが**戻る**。速度は大きく落ちる。画面が赤くなる |
| 帯の外に 1.3 秒いつづける | スローモーションが解ける（スローは丁寧な受け渡しのための助けです） |
| CORE を落とした（自由落下を検出） | 「BATON DROPPED!」。速度が 3 割になり、1.2 秒は拾う時間 |
| ゲージが満タンになる前にゾーンを出た | **+3 秒のペナルティ**（居酒屋ルール・既定）、または**失格**（公式ルール）。設定で切り替え |

- 帯の幅は、角速度 ±90 °/s・加速度 ±0.2 G（重力を除く）です。**いちばん大きく動いた 1 軸**で判定するので、どれか 1 軸がぴくっと動いただけでも波形に出て、速度が落ちます。
- ゾーンに入ってから 0.35 秒は、動いていても速度は余分に落ちません（振りは急には止められないため）。
- 満タンになった時点で残っていた速度が、次の走者の出だしの速度です。結果には受け渡しごとの「残ったバトンの速度（%）」と評価（S〜D、×）が出ます。
- 受け渡しが終わるまで、次の走者はいくら振っても進みません。

### スタート

号砲の前に動いた／0.100 秒より速く反応した場合、居酒屋ルールではスタートのやり直し、公式ルールでは失格です。

### 記録の目安

- タイムは振りの強さでほぼ決まります（上の表）。受け渡しが雑だと、そこから 3 秒ほど遅くなります。
- キーボードの `Space` は秒速 11.4m の振りとして扱います（完璧に操作して 37.12 秒）。
- **実際に人が振ったときの値はまだ測っていません。**

## しくみ（センサーの読み方）

加速度とジャイロだけを使います（`gotConvertedAcc` / `gotConvertedGyro`）。読み方は `../GAME-SUPER-START/motion.js` と共通です。

- **振りの強さ**：角速度の大きさ（3 軸を合わせた値、°/s）を 0.35 秒でならした値。あわせて、重力を除いた加速度の大きさ（G）も同じようにならし、`振り ÷ 800 °/s` と `加速度 ÷ 5 G` の大きいほうを使います。
- **手の動き（受け渡し）**：角速度 3 軸と、重力を除いた加速度 3 軸（0.4 秒のハイパスフィルタ）のうち、帯の幅に対していちばん大きい 1 軸。
- **落下**：加速度の大きさが 0.3 G 未満の状態が 0.15 秒続いたとき。強く振っている最中に誤って出ないかは、実機でまだ確かめていません。
- **センサーが途切れたとき**：直前まで届いていた信号が止まったあいだは、「動かしていない」とはみなしません（ゲージは勝手にたまりません）。

数値はすべて `relay.js` の `RELAY_DEFAULTS`・`SWING_DEFAULTS`・`CALM_DEFAULTS`、`motion.js` の `MOTION_DEFAULTS` にあります。設定ドロワーで「トップスピードになる振りの強さ」「帯の幅」「受け渡しに必要な時間」を変えられます。

## 画面のつくり

- **直線は 110m しかない**ので、400m をそのまま置けません。受け渡しが終わった瞬間にカットを入れ（白いフラッシュ）、次の区間を直線の上に置き直しています。ライバルも同じ置き直しをするので、前後の距離は変わりません。フィニッシュゲートはアンカーの区間だけ出します。このため、トラックに描かれた「10m」「20m」などの距離表示は、2 走以降では実際の距離と合いません。
- **音の出力が遅い機器（Bluetooth イヤホンなど）**では、号砲の音が 0.15〜0.2 秒遅れて聞こえます。号砲の基準時刻と画面の合図は音に合わせてあります。接続パネルに注意書きが出ます。

## Run

リポジトリのルートでローカルサーバを起動して、Chrome で開きます。

```text
http://localhost:8767/examples/GAME-SUPER-RELAY/
```

three.js（0.160）を unpkg から読み込むため、ネットワーク接続が必要です。
コンソールの `relayDebug` で状態を確認できます（`relayDebug.race`、`relayDebug.input`、`relayDebug.shakePeak` など）。
