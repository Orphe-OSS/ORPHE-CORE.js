# SUPER VIRTUAL START — 号砲リアクション

> **Status**: 公開（2026-11-18）。2026-11-17 に ORPHE CORE 2.0（CR-2）と CORE 3.0（CR-3）の実機で遊び、記録された生データで判定を確かめました。しきい値と速度の物差しは少人数の記録から決めた値で、設定から変えられます。

ORPHE CORE を 1 個、手に持って遊ぶ「スタートの一瞬」だけのゲームです。
[SUPER VIRTUAL HURDLE](../GAME-SUPER-HURDLE/README.md) と同じ夜のスタジアムで、100m 決勝のスタートラインに立ちます。

## 遊び方

タイトルの「HOW TO PLAY」に、持ち方と遊び方が 3 コマの動く絵で出ます（① にぎる ② とめる ③ うごかす）。絵は `index.html` の SVG、動きは `style.css` の「HOW TO PLAY」で、リレーも同じ部品を使います。

1. 右上の **ORPHE CORE** パネルのスイッチを ON にして、CORE を 1 個つなぎます（つながなくても `Space` キーで遊べます）。
   名前を入れられます（任意）。タイトルと、結果の画面（RETRY の前）のどちらでも入れられます。入れておくと、ランキングにその名前で自動で登録され、生データの記録にも入ります。次の人は、結果の画面で名前を書き換えてから RETRY します。
2. **START** を押すと「ON YOUR MARKS（位置について）」。
3. 「SET（用意）」が出たら、CORE を持った手を**止めます**。止まったのを確認すると、ゲージが満タンになって消えます。
4. そこから 1 秒以上あとの、**読めないタイミング**で**号砲**が鳴ります（半分は 2 秒以内、10 回に 1 回は 4 秒以上、最長 6 秒）。鳴った瞬間に、CORE を振る・突き出す・たたくなど、とにかく動かします。
5. 号砲から動き出しまでの時間（反応時間）が出ます。

| 入力 | ORPHE CORE | キーボード |
| --- | --- | --- |
| SET | 手を止める | なにもしない |
| スタート | 動かす | `Space` |
| もう一度 | — | `Space` / `Enter` |
| タイトルへ | — | `Esc` |

### ルール

本物のスタートと同じです。

- **SET で全員が止まるまで、号砲は鳴りません。** 動いているあいだは待たれるだけで、反則ではありません。8 秒たっても止まらなければ「STAND UP」でやり直しです。
- **止まったあと、号砲の前に動いたらフライング**（不正スタート）。
- **号砲までの待ち時間は指数分布**です。どれだけ待ったあとでも「次の瞬間に鳴る確率」が変わらないので、間合いを覚えて合わせることができません（以前は 1.1〜2.4 秒の一様な乱数で、何回かやると読めました）。
- **号砲から 0.100 秒より速い反応もフライング。** 音を聞いてから動くには速すぎる、という世界陸連の基準です。
- 号砲から 2.5 秒動きがなければ「NO START」です。

結果画面には、反応時間・評価（S〜E）・0.100 秒の線が入った目盛り・決勝 8 人の反応時間の中での順位が出ます。
ライバル 7 人の反応時間は 0.128〜0.205 秒の乱数です。名前を入れるとこのブラウザのランキングに残ります。

| 評価 | 反応時間 |
| --- | --- |
| S　世界の決勝レベル | 0.130 秒未満 |
| A　トップ選手なみ | 0.160 秒未満 |
| B　するどい反応 | 0.200 秒未満 |
| C　いいスタート | 0.260 秒未満 |
| D　もう少し | 0.350 秒未満 |
| E　出遅れ | それ以上 |

## 反応時間の精度について

競技用の計測値ではありません。次の 2 つの遅れがあります。

- **音の遅れ**：号砲の時刻は、ブラウザが報告する音声出力の遅れ（`baseLatency + outputLatency`）を足して決めています。本体のスピーカーで約 0.02 秒、Bluetooth イヤホンでは 0.15〜0.2 秒です。**画面のフラッシュとライバルの飛び出しも、音が聞こえる時刻に合わせて出します。**（2026-11-16 の実機テストでは、AirPods につないだ状態でフラッシュだけ先に出していたため、フラッシュを見て動くと 0.1 秒より速い反応＝フライングになっていました。）遅れが 0.06 秒以上あると、接続パネルに注意書きが出ます。報告されない遅れがある機器（テレビなど）では、そのぶん反応時間が長く出ます。
- **センサーの遅れ**：サンプルの時刻は、CORE が付けたタイムスタンプをページの時計に合わせて使っています（受信の揺らぎは消えます）。それでも最短の送信時間（おおよそ 0.01〜0.03 秒）は残り、そのぶん遅く出ます。設定の「センサーの遅れ補正」で引けますが、実機で測った値がまだ無いので既定は 0 です。
- **CORE 2.0（Bluetooth の名前が CR-2）は、さらに粗くなります。** 2026-11-17 の記録で分かったことです。CORE 2.0 の通知は 50 Hz・8 bit（1 目盛りが 0.13 G・18 °/s）で、サンプルに時刻が付いていません。届いた時刻をそのまま使うので、時刻は約 30 ms ごとにまとまり、送信の遅れもそのまま乗ります（その日の 4 本は 0.27〜0.31 秒と 0.60 秒）。反応時間を細かく比べたいときは、CORE 3.0（CR-3。約 200 Hz・16 bit・時刻つき）を使ってください。どちらで測ったかは、記録の `meta.sensor.name` に入ります。

キーボードは `keydown` イベントの時刻をそのまま使います。

## しくみ（センサーの読み方）

加速度とジャイロだけを使います（`gotConvertedAcc` / `gotConvertedGyro`）。

- **止まっている**：静止中の加速度（重力）からのずれが 0.12 G 未満、かつ角速度が 40 °/s 未満。持つ向きは問いません。
- **動き出した**：ずれが 0.35 G 以上、または角速度が 120 °/s 以上になったところで「動いた」と分かります。反応の時刻は、そこから最大 0.15 秒さかのぼって探した**動きの立ち上がりの始まり**です。手に持ったセンサーでは、しきい値を超えるのは動き始めてから数百分の 1 秒あとで、それを反応時間にすると遅く出るためです（2026-11-17 の実機テストで 0.3 秒前後と出ていました）。立ち上がりの始まりは、しきい値までの波形の「折れ曲がり」で決めます。手がゆっくり傾いたり力んだりしていた部分は含めません。結果カードの波形には、動き始め（実線）としきい値を超えた時刻（点線）の両方が出ます。
- **センサーが途切れたとき**：直前まで届いていた信号が止まったあいだは、「止まっている」とはみなしません（号砲は鳴りません）。

### 判定に使っている波形を見る

CORE をつなぐと、判定に使っている動きの大きさ（加速度・角速度）が 3 か所に出ます。目盛りは「しきい値を 1」とした値で、黄の線が「動いた」、緑の点線が「静止」です。

- **接続パネル**：いつでも、直近 4 秒。
- **SET のあいだ**：画面の下に、直近 3 秒。
- **結果カード**：その 1 本の、号砲の前後。号砲の線、フライングになる 0.1 秒の帯、しきい値を超えた時刻が入ります。「計測データ」ボタンで、波形と時刻を JSON で保存できます。判定がおかしいと感じたときは、このファイルで確かめられます。

しきい値は設定ドロワーの「静止の許容」「動き出しのしきい値」で変えられます。**これらの既定値は机上で決めたもので、実機ではまだ合わせていません。**

## ファイル構成

| File | Role |
| --- | --- |
| `index.html` | マークアップと、CORE の接続 UI の初期化 |
| `main.js` | 進行（タイトル → コール → 号砲 → 結果）、結果カード、ランキング |
| `start.js` | スタートの手順とフライングのルール（DOM 非依存） |
| `motion.js` | センサーの読み方：静止・動き出し・振りの強さ・落下、サンプル時刻の補正（DOM 非依存） |
| `scope.js` | 判定に使っている波形の表示（ライブ・結果カード・リレーの生波形） |
| `recorder.js` | 生データの記録。1 本ごとに加速度・角速度の生データ（CORE 3.0 は約 200 Hz、CORE 2.0 は 50 Hz）と判定の時刻、入力した名前をこのブラウザ（IndexedDB）に保存し、JSON で取り出す。リレーも同じ場所に保存する。**はじめから ON** で、接続パネルの「生データを記録 / REC」で切れる。ON のあいだは 1 本ごとに「ダウンロード」フォルダへも JSON を自動で保存する（設定で切れる。2 回目の保存で Chrome が複数ダウンロードの許可を聞く） |
| `stage.js` | スタジアムの用意。`../GAME-SUPER-HURDLE/` の `world.js` / `runner.js` / `fx.js` / `audio.js` を読み込み、カメラ・ライバル・毎フレームの更新をまとめる。[SUPER VIRTUAL RELAY](../GAME-SUPER-RELAY/README.md) もこれを使う |
| `style.css` | この種目のスタイル（土台は `../GAME-SUPER-HURDLE/style.css`） |

スタジアム・走者・音は SUPER VIRTUAL HURDLE のモジュールをそのまま読み込んでいます（コピーしていません）。
そのため、`../GAME-SUPER-HURDLE/` の `.js` / `.css` を変えたら、**このページのビルド ID（`?v=`）も同じ値に変えてください**。
`tests/super-start-build-id.test.js` が、3 つのページの ID の不一致と import map の登録漏れを検出します。

テスト：`tests/super-start-motion.test.js`（静止・動き出し・時刻補正・スタート手順・フライングの境界）。

## Run

リポジトリのルートでローカルサーバを起動して、Chrome で開きます。

```text
http://localhost:8767/examples/GAME-SUPER-START/
```

three.js（0.160）を unpkg から読み込むため、ネットワーク接続が必要です。
コンソールの `startDebug` で状態を確認できます（`startDebug.attempt`、`startDebug.tracker.last` など）。
