PURPOSE

「必ず settle する」「キャンセルは静か」「失敗は code 付き」の 3 点を確認する

旧 begin() は、SENSOR_VALUES / 両方 の分岐で startNotify() に .catch が無く、 notify 失敗や未知の通知種別で Promise が永久に settle せず、await が戻ってきませんでした。 また末尾の .catch が本物の失敗を握りつぶして undefined を返していました。 v1.5.0 では 成功 → 結果文字列／ダイアログのキャンセル → undefined（onError も呼ばない）／ 本物の失敗 → error.code 付きの reject になります。

各ボタンは settle 監視つきで実行され、20 秒たっても戻らない場合は NOT SETTLED として記録します。

  • D は実機なしで実行できます（未知の通知種別 → 旧実装のハング再現ケース）。最初に押してください
  • A はダイアログが出たら 「キャンセル」を押します。赤いエラーが出ず、onError 呼び出し が増えなければ OK
  • C は CORE の電源を切った状態（またはペアリング済みで圏外）で押します。3 秒で CONNECT_TIMEOUT になれば OK
